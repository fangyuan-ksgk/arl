1 · The six tricks

Trick 1 — Container-free sandboxing with proot

  • No CAP_SYS_ADMIN, user-ns blocked → Docker/rootless/bubblewrap all fail.
  • proot -b $TMP:/app -w /app is a userspace ptrace chroot — zero privilege.
  • Agent writes /app/… and the pytest verifier's absolute /app/… checks hit the same temp dir; tests stay host-side.

Trick 2 — Multi-turn rollout + loss masking

  • Re-render the full conversation each turn → generate → env.step → append → loop.
  • Train only on generated tokens (mask=1); observations & image tokens are masked out (mask=0).
  • Deferred-offset trick reads obs tokens from the next render — one fewer call per turn.

Trick 3 — GRPO: group-relative advantage, no critic

  • Sample a group of G completions, score each, advantage Aᵢ=(rᵢ−mean)/std.
  • The group mean is the baseline — that's the whole simplification vs PPO.
  • pass@8 ≫ pass@1 ⇒ the model can solve it but unreliably; GRPO sharpens it. Partial credit = denser gradient.

Trick 4 — The multimodal parquet trap (a real bug we fixed)

  • Mixed image+text content lists can't share one Arrow struct → to_parquet JSON-encodes each part to a string.
  • Lenient local apply_chat_template passes; strict vLLM /render rejects strings → crash.
  • Fix = decode strings back to dicts before render. Fix the data, not the model.

Trick 5 — One A100, two ceilings (the OOM that bit us all day)

  • colocate_all time-shares 80 GB VRAM between vLLM and FSDP; tune gpu_mem_util, enforce_eager, max_model_len.
  • Ray sees the container cgroup (~116 GB), not the 1007 GB host. A full batch's FSDP forward_backward (~58 GB) blew past the 95% kill line.
  • Bonus gotcha: a leaked 74 GB runaway from a crashed rollout squatting in the shared cgroup OOM-killed a fresh run at init. Reap orphans; watch both meters.

Trick 6 — ToyBox: self-verifying agentic loop + partial credit

  • Model emits ```python/```bash, runs in a sandbox, reads output, iterates, ends with <answer> or TASK_COMPLETE.
  • Hidden checks[] (answer/file/stdout/pyfunc) → reward = mean(checks) ∈ [0,1].
  • A buggy is_prime passing 6/9 cases scores 0.67, not 0 — denser signal than all-or-nothing.

3 · miniGRPO — hack the algorithm

One GRPO step, in plain PyTorch (no Ray/vLLM/FSDP). The advantage is a swappable function — exactly the seam tree_trainer.TreeTrainer._compute_loss overrides:

prompts ─> sample G completions (sandbox) ─> rewards
                                              │
   ┌──── THE SEAM (edit me) ◀─────────────────┘
   │  group_zscore:  aᵢ = (rᵢ − mean_g)/(std_g+ε)     # scalar
   │  to_per_token:  flat | opa | <your idea>          # scalar -> per token
   └──────────────────────┬───────────────────────────┘
                          ▼
   loss = −mean( advantageₜ · logp(tokenₜ) )           # == GRPO

Built-in modes in ADVANTAGE_MODES: flat (vanilla GRPO) and opa (your Optimistic Prefix Advantage — imported straight from arl/src/tree_trainer.py, builds a per-group prefix trie, credits each token with the best reachable continuation). Add your own:

def adv_myidea(rewards, group_ids, token_seqs):
    scal = group_zscore(rewards, group_ids)   # reuse the scalar step
    return [...]                              # per-token list[list[float]]
ADVANTAGE_MODES["myidea"] = adv_myidea
# python minigrpo.py --train --mode myidea

Scaling to SkyRL (Ray/FSDP/vLLM): SkyRL has a plug-in registry — no core edits. Register @register_advantage_estimator("opa") (see examples/train/algorithms/custom_advantage_estimator/) and run with trainer.algorithm.advantage_estimator=opa. ⚠️ One wrinkle: the estimator only receives (rewards, response_mask, index), not the response token ids OPA needs — thread them in from data["responses"] in Trainer.compute_advantages_and_returns (skyrl/train/trainer.py:960). Prototype in miniGRPO (token ids are right there in each Rollout), then port the validated function. Full detail in minigrpo/README.md.
